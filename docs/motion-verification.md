# 手势与真机验证

DeskPace 的面板显示 T90，即从松手到走完剩余位移 90% 的时间。窗口何时能收到点击需要单独测量。以下记录均来自内建屏；换系统版本或显示器后，应在同一目标上重新比较原速与调速。

## 运行回归测试

在装有 Xcode Command Line Tools 的 Mac 上，从菜单栏退出 DeskPace，给运行测试的终端授予辅助功能权限。让光标所在的显示器至少有两个相邻空间。进入项目目录后运行：

```sh
./Tests/verify-motion.sh
```

脚本编译一个带手势引擎的临时测试程序。它优先选下一个空间，没有时选上一个；也可传 `--previous` 或 `--next` 指定方向。测试会实际切换桌面，并尝试点击起始空间中的临时窗口。要测全屏 App 的点击等待时间，从该 App 所在的全屏空间开始。

| 场景 | 测试核对的结果 |
| --- | --- |
| 1×、3×、4× 往返 | 回到同一目标后，分别记录 T90、系统报告目标成为当前空间的时间、窗口收到点击的时间。 |
| 接近落点 | 核对结束事件发出时距目标不超过 2 点，比较 85% 至 95% 的分段用时；4× 去程额外丢弃一次位置更新。 |
| 慢划、停住再松手 | 对比 1× 和 3× 的 T90，并确认到达相邻空间。 |
| 取消回弹 | 对比 1× 和 4× 的 T90，并确认到达起始空间。 |
| 立即反向切回 | 在 3× 去程已接近目标、系统仍报告起始空间时开始回切，核对回程 T90 和最终空间。 |

## 已有实测记录

以下数据来自 macOS 27.2.1 的内建屏。测试程序以相同的位移和松手速度切回同一个目标，并在真实桌面上逐帧读出位置。点击列记录目标窗口实际收到鼠标按下事件的时刻，包含每隔约 20 毫秒尝试一次点击的采样误差。

独立 App 获得辅助功能权限后，也记录了直接在触控板上完成的 11 次 3× 切换。走完 90% 位移的实测范围为 104–107 毫秒，中位数 105 毫秒。

| 目标 | 所选倍率 | 走完 90% 位移 | 目标窗口收到点击 |
| --- | ---: | ---: | ---: |
| 普通桌面 | 1× | 304 毫秒 | 941 毫秒 |
| 普通桌面 | 3× | 102 毫秒 | 332 毫秒 |
| 普通桌面 | 4× | 77 毫秒 | 257 毫秒 |
| 全屏 App 所在空间 | 1× | 301 毫秒 | 953 毫秒 |
| 全屏 App 所在空间 | 3× | 100 毫秒 | 333 毫秒 |
| 全屏 App 所在空间 | 4× | 77 毫秒 | 262 毫秒 |

0.1.2 在同一台 Mac 上复测了慢划和回弹。慢划收尾在 1× 和 3× 时分别用了 314 和 106 毫秒走完 90% 位移，停住再松手分别用了 312 和 104 毫秒。取消回弹在 1× 时用了 316 毫秒，在 4× 时用了 77 毫秒，两次都回到原桌面。

0.1.1 修复了接近目标桌面时先停顿、再滑完一小段的问题。旧版在另一组实测中提前约 175 点结束了手势。0.1.1 用每次切换的真实位移校准手势行程。复测中，约 2× 的四次触控板切换分别耗时 151–157 毫秒走完 90% 位移。结束手势时距落点为 0–1 点。

0.1.4 修复了连续回切时回程降到原速的问题。在 3× 下，去程松手后约 60、150、230 毫秒开始反向划动，均回到起始桌面。回程 T90 从修复前的约 310 毫秒缩短到约 100 毫秒。

## 兼容性与待验证配置

macOS 27.2.1 内建屏已有上述真机结果。macOS 26 已做 SDK 类型检查，仍需在真机上验证。构建脚本同时编译 arm64 和 x86_64，架构覆盖情况不能代替手势实测。

公开分发前，还需在外接屏上分别验证「显示器具有单独的空间」开启和关闭两种配置：将光标移到目标屏，比较普通桌面及全屏空间的切换、回弹、快速回切和点击等待时间。所有显示器共用同一个用户倍率。
